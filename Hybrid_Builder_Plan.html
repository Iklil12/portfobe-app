Technical Design Document: Hybrid Modular Builder Migration

1. Executive Summary

Dokumen ini adalah cetak biru (blueprint) strategis untuk merombak arsitektur rendering Portfo.be. Berdasarkan keputusan bisnis untuk memberikan kebebasan kustomisasi (drag-and-drop) tanpa mengorbankan pengalaman instan (theme presets), kita akan bermigrasi dari Monolithic Theme Architecture menuju Block-Based Hybrid Architecture.

Sebagai Senior Systems Architect, saya telah menyusun peta jalan (roadmap) ini untuk meminimalisir risiko kegagalan sistem (downtime) dan memastikan transisi kode yang mulus.

2. Analisis Arsitektur (Sebelum vs Sesudah)

Arsitektur Saat Ini (Monolitik)

Saat ini, satu tema (misalnya CinematicTheme) adalah satu file raksasa yang berisi semua seksi (Hero, About, Projects, Awards) yang urutannya dikunci permanen (hardcoded).

  • Database -> Membaca themeTemplate: 'cinematic'
  • Halaman memanggil komponen <CinematicTheme /> secara utuh.

Arsitektur Baru (Modular Block Builder)

Nantinya, halaman portofolio tidak lagi membaca 1 file tema utuh. Ia akan mengambil sebuah Array (daftar urutan) blok dari database dan merendernya satu per satu menggunakan Dynamic Block Renderer.

  • Database -> Mengambil Array dari tabel PageBlock
  • Halaman memanggil <DynamicBlockRenderer blocks={data} />
  • Renderer akan melooping blok: Index 0 memanggil <CinematicHeroBlock />, Index 1 memanggil <MinimalistAwardsBlock />, dst.

3. Desain Database (Skema Prisma)

Kita perlu menambahkan tabel baru untuk melacak urutan dan konfigurasi masing-masing blok milik pengguna.

// Penambahan model baru di schema.prisma
model PageBlock {
  id          String   @id @default(uuid())
  userId      String
  
  // Tipe blok, misal: 'CINEMATIC_HERO', 'ACID_GALLERY'
  blockType   String   
  
  // Urutan render dari atas ke bawah (0, 1, 2, 3...)
  orderIndex  Int      @default(0)
  
  // Sakelar untuk Toggle Visibility (ON/OFF tanpa menghapus data)
  isVisible   Boolean  @default(true)
  
  // Konfigurasi spesifik per blok (Warna teks khusus, spacing, dll)
  configJson  String?  @db.Text
  
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId, orderIndex]) // Diindeks agar fetching berurutan sangat cepat
}

4. Strategi Pemecahan Komponen (Component Refactoring)

Aturan Isolasi Blok: Setiap file blok tidak boleh membocorkan CSS-nya ke luar kontainernya agar tidak terjadi tabrakan desain.

Struktur Direktori Baru:

components/
└── blocks/
    ├── cinematic/
    │   ├── CinematicHeroBlock.tsx
    │   ├── CinematicProjectsBlock.tsx
    │   └── CinematicAwardsBlock.tsx
    ├── acid/
    │   ├── AcidHeroBlock.tsx
    │   └── ...
    └── shared/
        └── BlockWrapper.tsx (Komponen HOC untuk menangani spacing antar blok)

5. Peta Jalan Eksekusi (Phased Roadmap)

Agar proyek raksasa ini tidak membebani sistem secara tiba-tiba, saya membaginya menjadi 3 fase progresif. Kita hanya akan maju ke fase berikutnya jika fase sebelumnya sudah 100% stabil.

  • FASE 1: Fondasi & Basis Data (Durasi: ~2 Hari)
    • Menambahkan model PageBlock ke schema Prisma.
    • Membuat API Endpoint CRUD untuk blok.
    • Membuat mekanisme Seeding (menyiapkan layout default).
  • FASE 2: Pembongkaran Komponen (Durasi: ~4 Hari)
    • Membedah 1 Tema Saja (misalnya CinematicTheme) sebagai uji coba (Proof of Concept).
    • Menulis DynamicBlockRenderer.
  • FASE 3: UI Builder di Dashboard (Durasi: ~5 Hari)
    • Menambahkan tab "Layout Builder" di halaman Dashboard.
    • Mengimplementasikan Drag and Drop.
  • FASE 4: Migrasi Skala Penuh (Durasi: ~2-3 Minggu)
    • Membedah sisa 20 tema lainnya.

6. Manajemen Risiko & Mitigasi

Risiko: Pengguna lama yang sedang live webnya bisa rusak (blank page) jika proses migrasi gagal.

Mitigasi: Kita akan membuat fitur ini sebagai fitur tersembunyi (feature flag) atau beta testing terlebih dahulu. Halaman publik akan mendukung dua mode (membaca SiteAppearance ATAU PageBlock) hingga migrasi 100% selesai.

7. Kemampuan & Keuntungan untuk User (Post-Launch Features)

  • Drag-and-Drop Layout: Menggeser posisi seksi secara bebas.
  • Strict Theme Integrity: Hanya bisa memakai blok dari tema yang aktif agar desain tidak rusak.
  • Singleton Dynamic Blocks: Seksi seperti Projects/3D hanya bisa digeser/disembunyikan (karena datanya tunggal dari DB).
  • Addable Static Blocks: Bisa menambahkan berulang kali seksi statis eksklusif milik tema (misal: Text Block, Timeline, Banner).
  • Live Instant Preview: Drag & drop langsung ter-update di iFrame tanpa loading layar.

8. Katalog & Registri Static Blocks (Panduan Maintenance)

Aturan konvensi penamaan (Registry) untuk blok di database: [NAMA_TEMA]_[NAMA_BLOK] (Contoh: CINEMATIC_MANIFESTO).

Nama Blok Kode blockType Deskripsi & Fungsi Utama
Manifesto / Quote *_MANIFESTO Tipografi raksasa (full-screen) berisi filosofi kerja. Sangat cocok untuk Cinematic atau Viewfinder.
Trusted By (Logos) *_CLIENT_LOGOS Marquee berjalan atau grid logo klien. Cocok untuk semua tema demi social proof.
Service Packages *_PRICING Tabel harga 3 kolom untuk freelancer berjualan paket.
Fun Facts (Counters) *_STATS_COUNTER Angka raksasa yang bergerak dari 0 ke target saat di-scroll.
FAQ Accordion *_FAQ Daftar Pertanyaan Sering Diajukan yang bisa di-expand.
Parallax Banner *_MEDIA_BREAK Pemisah visual berupa foto/video resolusi tinggi dengan parallax effect.
Career Journey *_TIMELINE Garis waktu statis berisi sejarah pendidikan/pekerjaan.
Massive CTA *_CTA_FOOTER Ajakan "Let's Work Together" berukuran raksasa tepat sebelum footer utama.
